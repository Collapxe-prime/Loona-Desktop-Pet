# Версионирование и локальная сборка

Корень приложения — папка с `main.py`, `VERSION`, `.gitignore` и этим документом.
Это самостоятельный корень будущего репозитория, а не весь каталог с архивами разработки.
Git пока не инициализирован. Скрипт сборки не выполняет команд Git.

Разделение рабочих и чистых исходников описано в `PROJECT-VERSIONS.md`.
Кэш pip, PyInstaller и временные файлы сборки хранятся в `build` на диске проекта.

## Версия и изменения

- `VERSION` — единственный источник номера. Он используется приложением,
  именем сборки и информацией версии Windows EXE.
- `CHANGELOG.md` — изменения подготовленной версии и раздел `Unreleased` для будущих изменений.
- `1.0.0` — номер версии, подготовленной к релизу; публикация выполняется отдельно.
- При будущем выпуске владелец меняет `VERSION`, оформляет раздел changelog
  и отдельно решает вопросы Git-тега, подписи и публикации.

## Одна команда сборки

На Windows x64 с Python 3.12 из корня проекта:

```powershell
py -3.12 build.py
```

Если Python 3.12 уже выбран в окружении, достаточно `python build.py`.
Скрипт создаёт изолированное `.build-venv`, устанавливает зависимости из
`requirements-build.txt`, запускает тесты, собирает PyInstaller EXE,
добавляет только перечисленные рабочие ресурсы и проверяет запуск EXE.
Первый запуск требует доступа к PyPI. Зависимости установлены только в окружение сборки.
Зафиксированы прямые и транзитивные зависимости сборки; фактически установленные версии
записываются в `BUILD-INFO.json`. Побайтовая идентичность EXE между сборками не обещается.

Проверка подготовки без загрузки зависимостей и компиляции:

```powershell
.\.venv\Scripts\python.exe build.py --check
```

Для запуска из исходников в новом окружении нужны зависимости из `requirements.txt`.
Номер можно проверить командой `python main.py --version`.

## Результат

```text
build/                                  временные файлы, проверки и PyInstaller
.build-venv/                            отдельный Python для сборки
dist/
  Loona-Desktop-<VERSION>-windows-x64/
    Loona-Desktop.exe
    _internal/                          Python и библиотеки
    assets/                             только рабочие PNG и JSON
    VERSION
    README.txt
    CHANGELOG.md
    BUILD-INFO.json
    SHA256SUMS.txt
  Loona-Desktop-<VERSION>-windows-x64.zip
  Loona-Desktop-<VERSION>-windows-x64.zip.sha256
```

Существующая сборка этой версии не перезаписывается. Чтобы пересобрать ту же
версию, сначала самостоятельно перенесите её результаты из `dist`.
Папка и ZIP — локальные артефакты, не автоматически опубликованный релиз.

PyInstaller собирает приложение на целевой ОС; инструкция основана на
[официальной документации PyInstaller](https://pyinstaller.org/en/stable/usage.html).
Используется папка с EXE и зависимостями, поэтому ресурсы доступны рядом с EXE,
без временной распаковки режима one-file.

## Что хранится в Git

Код, актуальные тесты и маленькие fixtures, документация, требования зависимостей,
скрипт сборки, VERSION, changelog и рабочие ресурсы приложения.

`.gitignore` исключает окружения Python, IDE, кэши, логи, личный `settings.json`,
архивы, резервные копии, результаты сборки и черновые ресурсы генерации.
Рабочие `manifest.json`, `quality-profile.json` и кадры явно разрешены.
При добавлении совершенно нового типа анимации проверьте allowlist ресурсов
в `.gitignore` и `release_assets()` в `build.py`.

Игнорирование не удаляет файл, который уже был добавлен в Git. Если репозиторий
будет создан поверх ранее отслеживаемых файлов, владелец должен проверить индекс;
этот сценарий не удаляет файлы из индекса автоматически.

## Настройки пользователя

Запуск из исходников сохраняет нынешние настройки в папке проекта.
Собранная версия использует `%LOCALAPPDATA%\LoonaDesktopPet`; assets и VERSION
остаются в папке установки. Во время проверок `LOONA_DATA_DIR` указывает внутрь
`build`, поэтому проверки не затрагивают личный конфиг.
